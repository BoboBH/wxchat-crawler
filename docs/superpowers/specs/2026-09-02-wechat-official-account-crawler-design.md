# 微信公众号文章爬虫 · 设计文档

日期:2026-09-02
状态:已经用户逐节确认

## 1. 背景与目标

用户维护一份公众号名单(10~50 个),希望每天定时自动抓取这些公众号新发布文章的 URL 及元信息,存入本地数据库,供后续使用。

**已确认的需求约束:**

| 维度 | 决定 |
|---|---|
| 公众号资质 | 无自己的公众号,不注册;使用个人微信扫码登录 PC 微信客户端 |
| 技术路线 | PC 微信客户端 + UI 自动化驱动 + mitmproxy 被动抓包 |
| 抓取范围 | 只抓增量新文章(上次之后新发布的) |
| 数据范围 | 只存文章 URL + 标题 + 发布时间 + 公众号名称;不下载正文,不做推送 |
| 名单规模 | 10~50 个账号 |
| 执行频率 | 每天两次(早/晚),运行时要求电脑开机且微信已登录 |
| 工具形态 | 命令行脚本 + Windows 任务计划程序;数据存 SQLite |

**验收标准:**计划任务连续 2 天自动运行;每轮结束后 SQLite 中能查到名单内各号新发布文章的 URL/标题/发布时间;失败账号有日志可查。

## 2. 总体架构

```
Windows 任务计划程序(每天 08:05 / 19:05 触发)
        │
        ▼
┌───────────────────────────────────────────┐
│ run_crawl.py(单轮主控)                    │
│  1. 启动 mitmdump 子进程 + 采集插件         │
│     (本地代理 127.0.0.1:8888)              │
│  2. 检查微信进程已运行且已登录               │
│  3. 从 accounts.yaml 读公众号名单           │
│  4. 逐个账号:                              │
│     uiautomation 操控微信窗口:              │
│     搜索框输入名称 → 打开公众号主页 →        │
│     进入历史消息 → 滚动 1~2 屏              │
│     (插件同时截获文章列表接口的 JSON,       │
│      解析出 标题/URL/发布时间 → 去重入库)    │
│  5. 遇到已入库的旧文章即提前结束该账号        │
│  6. 结束后:关闭代理、恢复系统代理设置、      │
│     写运行日志、输出本轮统计                 │
└───────────────────────────────────────────┘
        │
        ▼
   data/crawler.db(SQLite)
```

**核心原理:**UI 自动化执行的是真实导航,微信客户端自行生成全新的合法会话参数请求文章列表接口,因此不存在密钥过期问题;mitmproxy 只被动阅读响应并提取文章,不主动发起任何请求,行为与真人浏览一致。

**关键数据来源:**公众号历史消息页 `mp.weixin.qq.com/mp/profile_ext?action=getmsg` 的 JSON 响应,含每篇文章标题、`content_url`(目标 URL)、发布时间;一次群发多篇文章(多图文)全部解析。

**首次部署需人工执行一次:**安装 mitmproxy CA 证书(README 提供步骤)、单账号试跑验证。

**已实测环境(2026-09-02):**Windows 11;PC 微信 **4.1.12.55**(`C:\Program Files\Tencent\Weixin\Weixin.exe`,进程名 `Weixin`,常驻运行中);Python 3.12.10(`D:\Python312`,用于创建项目虚拟环境 `.venv`)。

## 3. 组件设计

### 3.1 目录结构

```
wechat-crawler/
├── config/
│   ├── accounts.yaml      # 公众号名单(每行一个名称,支持注释)
│   └── settings.yaml      # 调度时刻、代理端口、滚动深度、各类超时
├── src/
│   ├── orchestrator.py    # 入口:启停代理、登录检查、遍历账号、汇总统计
│   ├── proxy_addon.py     # mitmproxy 插件:过滤目标接口 → 交给 parser → 入库
│   ├── wechat_bot.py      # UI 自动化封装:搜索/打开主页/进历史消息/滚动/关闭
│   ├── parser.py          # 纯函数:接口 JSON → 文章记录(不含 IO,便于测试)
│   ├── db.py              # SQLite:建表、去重写入、增量水位查询
│   └── version_check.py   # 微信版本检测 + 代理端口/证书环境自检
├── data/crawler.db
├── logs/                  # 每轮一个日志文件
├── tests/                 # parser 与 db 的单元测试 + 真实抓包 JSON fixture
├── install_task.ps1       # 一键注册/注销 Windows 计划任务(08:05 与 19:05)
├── run_crawl.py           # 命令行入口
└── requirements.txt       # mitmproxy、uiautomation、pyyaml(无其他重依赖)
```

### 3.2 数据模型(SQLite,3 张表)

| 表 | 字段 | 说明 |
|---|---|---|
| `accounts` | id, name(唯一), last_crawled_at, max_publish_time | `max_publish_time` 为增量水位线 |
| `articles` | id, account_id, url(唯一), title, publish_time, created_at | 按 URL 去重,重复插入自动忽略 |
| `crawl_runs` | id, started_at, finished_at, ok_count, fail_count, new_count | 每轮一条,便于排查 |

### 3.3 增量停止逻辑

打开某账号历史消息后,每解析出一篇即与该账号水位线比较;一旦连续出现"发布时间 < 水位线 − 2 天重叠"的文章,立即停止滚动、切下一个账号。新账号(无水位线)默认抓最近 2 屏。

### 3.4 命令行接口

- `python run_crawl.py` — 正常单轮抓取(计划任务调用)
- `python run_crawl.py --account 某公众号名` — 单账号试跑(联调/新账号验证)
- `python run_crawl.py --check` — 环境自检(微信版本/代理端口/证书),不抓取

## 4. 错误处理

| 场景 | 处理 |
|---|---|
| 微信未运行/未登录/找不到搜索框 | 本轮立即中止,日志提示"请登录微信后等待下一轮" |
| 某账号搜索无结果/打开超时(90 秒无新数据) | 标记该账号失败,继续下一个 |
| 代理端口被占用 | 启动前自检报错退出 |
| mitmproxy 证书未安装 | 提示执行一次性安装步骤后退出 |
| 接口 JSON 结构变化(微信改版) | 解析异常按 0 篇计,日志记录原始响应片段供排查 |

## 5. 风控与已知风险

**风控策略(模拟真人,量极小):**账号间随机间隔 20~60 秒;每轮账号顺序打乱;每号每轮只滚 1~2 屏;每天仅 2 轮。总量约 50 号 × 2 轮 = 每天 100 次真实浏览,远低于人工使用强度。

**已知风险与对策:**

1. **微信 4.x 的 UI 自动化(最主要风险)**:实测环境为微信 4.1.12.55。4.x 重写了客户端 UI,老牌开源库 wxauto 主要支持 3.9.x,对 4.x 支持不完整。对策:首选直接用 `uiautomation` 库探测 4.1.x 的 UIA 控件树(搜索框、列表项是否可寻址),可行性尖峰阶段先验证;若 4.x 控件树不可用,降级方案为并行安装微信 3.9.x + wxauto 模式。适配成本限于 `wechat_bot.py` 单模块;运行时检测版本并告警。
2. **微信 4.x embedded 页面是否走系统代理**(需实测):4.x 渲染公众号历史消息页的内嵌浏览器若绕过系统代理或不信任自签证书,抓包即失效。对策:可行性尖峰阶段手动配置 mitmproxy + CA 证书,打开任一公众号历史消息,确认能截获 `profile_ext` 响应。尖峰两项(UIA + 抓包)任一失败,需回头重议技术路线,先验证再动工。

## 6. 测试策略

- `parser.py` 与 `db.py`:单元测试覆盖(真实抓包 JSON fixture、内存 SQLite),含多图文解析、URL 去重、水位线判断。
- `wechat_bot.py` UI 部分无法自动化测试 → 用 `--account X` 单号试跑模式人工验证。
- 里程碑顺序:①可行性尖峰(在微信 4.1.12.55 上验证 UIA 控件树可寻址 + mitmproxy 能截获 `profile_ext`)→ ②抓包解析入库跑通单号 → ③全量名单跑通 → ④注册计划任务,观察两天自动运行。

## 7. 运行环境要求(已实测)

- Windows 11,用户已登录桌面(计划任务仅"用户登录时运行",UI 自动化需要交互桌面会话)
- Python 3.12.10,位于 `D:\Python312`;项目使用其创建虚拟环境 `.venv`
- PC 微信 4.1.12.55(`C:\Program Files\Tencent\Weixin\Weixin.exe`),运行时处于已登录状态;版本更新需重新适配
- mitmproxy(mitmdump)+ 本机 CA 证书已安装
